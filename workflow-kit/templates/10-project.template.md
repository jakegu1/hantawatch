# 〈项目名〉— 项目规则（模板，填空后存为 rules/10-project.md）

一句话定位：〈给谁解决什么〉。读 @docs/PRD.md（做什么+不做什么）、@docs/PLAN.md（任务顺序）。
阶段：〈①全新 / ②收口 / ③打磨〉。

## 技术栈（不经询问不得替换）
- 〈语言/框架/存储/部署/测试工具〉

## Session boundaries（硬性）
- 〈多 Agent〉：给一批任务时按序自主推进，每个 /goal→实现→验证→verifier→报 3 行→下一个。
- 〈单 Agent：同一个 Agent 既设计又写码 → 焊死目标/执行墙〉：每个任务必须先 /goal 复述
  并停下等"go"，**禁止把"自己觉得该做的"直接变成代码**。
- 仅在 ①真实歧义/范围/设计取舍 ②verifier 判 NOT DONE 且修复超 allowlist ③需人工测试 时停。
- 卡壳 ~30 分钟 / ~5 次失败即停下报阻塞。
- 只改当前任务 allowlist 内文件；新建 allowlist 外文件先问。绝不提交密钥。

## 完成的定义（按完成判定方式填；可分层）
- 〈纯逻辑/可自动验层〉：〈build/typecheck/单测〉通过。
- 〈集成/UI/人工层〉：〈冒烟脚本 + 验收清单逐条勾 + 人工确认〉。
- 〈若 Eval-driven〉：eval 分达标（打分器须先校尺）。
- 通用：AC 满足 + diff 只碰 allowlist + 未引入越界需求 → 报 3 行总结后停。
- 〈可选：项目特有红线，如"触及 X 的改动必须先有覆盖 Y 的测试"〉

# BOOTSTRAP — 在任意新/在途项目里启动工作流

> 用法：把下面「===」之间整段，发给该项目里的规划者（Claude Code / 对话）。
> 它会先探测仓库现状（已有 CLAUDE.md/README 等一律 merge 不覆盖），再反问你 5 题，
> 再生成/补全这个项目专属的 rules / PRD / PLAN / CLAUDE.md。
> 同一段 prompt 同时适用于全新项目和开发中项目——区别由探测和第 2 题（阶段）自动处理。
> 你不需要预先填任何模板——这条 prompt 就是即插即用的部分。

===
我要把一套"三角色三闸门"工作流落到**这个**项目。开始前先反问我，**不要假设、不要直接写代码**。

## 第 0 步：先探测现状，再决定新建还是合并（已有文件绝不覆盖）
先扫一眼仓库，报告是否已存在：CLAUDE.md / README.md / rules/ / docs/PRD.md / docs/PLAN.md。
**已存在的文件是资产，不是障碍，一律 merge 不 overwrite。** 按下列规则处理，且每个合并先给我看 diff、逐段问我保留/追加/跳过，不要静默替我决定：

- **CLAUDE.md 已存在**：保留原文（尤其架构地图、Gotchas、命令——这是积累出来的实战记忆，最值钱）。
  只对照模板**补缺口**：通常缺「这一注 why」「范围 binding + 指向 PRD 的 OUT-OF-SCOPE」「分层完成定义」
  和指向 rules/docs 的 @import 几行。把缺的**追加**进去，不动已有内容。若超 ~200 行，提示我精简而非堆叠。
- **README.md 已存在**：基本不碰——它是给人看的项目说明，不是工作流文件。最多在末尾加一行指向 WORKFLOW.md / CLAUDE.md。
  绝不把工作流内容塞进 README。
- **rules/ docs/PRD/PLAN 已存在**：逐个对照模板，缺什么补什么，冲突段落给 diff 让我裁决。
- **都不存在（全新项目）**：正常新建，无冲突。

探测完，再继续问下面 5 题。

先问我这 5 题（基于我的答复，逐项决定脚手架形态）：

1. **项目类型**：web / 后端 / 数据·ML / 内容·SEO / 其他？技术栈？
2. **当前阶段**：
   ① 全新没代码　② 已有 vibe 代码在跑、要补规格收口　③ 已成型要打磨。
3. **这版"完成"= 一句话**：让**谁**、完成**什么动作**，就算第一版成了？
   （要具体到人和动作，不要"做一套完整的 X"。）
4. **坚决不做的 3–5 条**（OUT-OF-SCOPE）：这版绝不碰什么？
   —— 若我答不出，用 3 个问题逼我把边界划出来。这条最重要。
5. **"完成"靠什么判定**：编译/测试　|　可量化指标·eval　|　纯人工　——可分层混合。
   这决定 verifier 怎么搭。

收到答复后，**按下列规则裁形态，再生成文件**（每生成一个文件先停下让我确认，不要进入写功能代码）：

## 裁形态规则
- **档位**：多周项目→Full；小工具/脚本→Lite（只 CLAUDE.md + 清单式 PLAN，跳过 PRD）；
  目标是质量/指标→Eval-driven（Full + eval harness）。默认 Lite，Full 要"挣"——别为小活上重仪式。
- **阶段 ②（收口）**：先把 T0 设为"补上正确性闸门"（本地能跑/能 lint/能测；否则验证是盲的）；
  PLAN 偏厚（收口任务序列），PRD 偏薄（主体是完成定义 + OUT-OF-SCOPE）。
- **阶段 ①（全新无规格）**：先用 3–5 个问题帮我把想法收敛成 PRD+PLAN，再生成。
- **阶段 ③（打磨）**：脚手架降档——PLAN 塌缩成 progress log，PRD 冻结只读。
- **单 Agent 场景**（同一个 Agent 既设计又写码，没有独立执行者）：在 rules 里把"目标/执行墙"
  焊死——每个任务必须先 /goal 复述并停下等"go"，禁止把"自己觉得该做的"直接变成代码。
- **verifier 按完成判定方式选形态**：有 build/test→直接用；有指标→先校尺(人工标几个样本对齐打分器)再爬升；
  纯人工→退化为"验收清单逐条勾 + 查 allowlist 越界"。

## 要生成的文件（已存在的按第 0 步 merge，不存在的新建；参照 kit 模板填空，不要照抄占位符）
- `CLAUDE.md`（脊柱，Claude Code 自动加载；@import 其余）——见 templates/CLAUDE.template.md
- `rules/00-core.md`（直接复用，不改）——见 kit
- `rules/10-project.md`（填技术栈 + session boundaries + 分层完成定义）——见 templates
- `docs/PRD.md`（逼我明确 OUT-OF-SCOPE）——见 templates；Lite 档可省
- `docs/PLAN.md`（拆小任务，每个带 AC + 文件 allowlist）——见 templates
- 若 Eval-driven：加 `docs/EVAL.md`（测试集 + rubric + 打分 + 校尺步骤）

全程遵循 rules/00-core.md 的五条行为护栏。
===

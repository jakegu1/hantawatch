## 0. 一句话结论

**不要再做"汉坦观察"，也不要急着做"多疾病仪表盘"。做「传言体温计」：
用户在小红书/微信刷到一条传染病消息，5 秒内拿到一句带来源和日期的"这事现在到底什么状态"。**

汉坦只是它的第一个实例。护城河不是数据量，是"每个数字都能点回官方原文"这套约束——
这套约束你已经用代码写死了（`guard.py` + `source`/`asOf` 铁律），别人抄不走的是这个，不是 UI。

## 1. 诊断：这不是"流量下滑"，是产品到期了

汉坦是**一次事件**。事件结束，流量归零，这是正常的，不是运营失败。
把它当"运营没做好"去补，会补错方向。

代码里能直接看到"到期"的样子（本次已修）：

| 现象 | 根因 |
|---|---|
| 首页 92 天停在「海外关注 🟡」 | `_has_active_outbreak` 只看累计病例 > 0，累计数永不下降 → 状态永远出不来 |
| 首页仍在讲"源头仍为 MV Hondius 邮轮疫情" | 疫情态没有"结束"这一档，只能一直讲下去 |
| 每日简报自己写着"8月27日WHO宣布邮轮汉坦疫情结束" | 简报层知道结束了，状态机不知道 |

也就是说：**工具没有"没事了"这个状态**。一个只会说"还在关注"的安心工具，
在真的没事的时候反而制造轻微焦虑——这正好和 PRD 第 2 节的赌注相反。

> 已修：新增 `resolved / 已平息` 档。用今天的线上数据实测，状态从
> `remote_watch` 变成 `resolved`，首页首句变成「已经 56 天没有新增确诊」。

**但这只是止损。** 状态修好之后，工具依然只覆盖一个已经结束的疫情。
真正的问题是下面这个：**没有下一个疫情，就没有下一次流量。**

## 2. 资产盘点：哪三样值钱，哪三样不值钱

### 值钱（这是可以复用的）
1. **采集 + 溯源管道**。WHO DON / ECDC / ArcGIS / Google News 抓取 → 允许列表过滤 →
   LLM 结构化抽取 → `guard` 阻断无源数字 → 合规命名审计。237 个测试保着。
   **这是三个月的工程量，且它和"汉坦"没有强绑定**——`news_leads.py` 里的
   `QUERIES` 目前只有一行 `("汉坦病毒", "zh-CN", "CN:zh-Hans")`。加病种＝加行。
2. **已验证的获客动作**：截图 → 小红书 → 数万曝光 → 500+ 粉丝。这是**被真实市场验证过**的，
   比任何增长假设都可靠。
3. **疾病无关的品牌 + 已备案小程序**。"病毒观察"这个名字没有把你锁死在汉坦上——这是当初的好决定。

### 不值钱（别在这上面继续投入）
1. **HPI 指数**。外人不知道 31 分是什么意思；平静期显示"一般关注"反而像在报警。
   保留在透明度面板给较真的人看，**但不要再放在首屏和分享卡的 C 位**（分享海报已改）。
2. **汉坦专属 UI**：血清型排行、邮轮事件页、Andes 距离尺。事件结束后它们是历史档案，不是产品。
3. **网页端**。你的用户在微信和小红书里，不在浏览器里；站点又托管在 Vercel（境内访问不稳）。
   Web 保留作为"可被搜索/可被引用的档案 + 海报生成器"就够了，**不要再往 web 加功能**。

## 3. 三条路，以及我的选择

| | A · 守株待兔 | B · 常年有用的工具 | C · 传言核查 |
|---|---|---|---|
| 做什么 | 低成本待命，等下一次爆发 | 出国健康 / 季节性疾病日历 | "我刷到的这条消息，现在什么状态" |
| 需求节奏 | 尖峰，间隔以年计 | 季节性（寒暑假 / 冬季） | **恒定**——传言不分季节 |
| 复用管道 | 100% | 40%（要接新数据源） | **85%**（加查询词 + 复用 guard） |
| 数据可得性 | 已验证 | 国家级 ✅ / 国内只到省级 | 已验证（就是现在这套） |
| 变现 | 无 | **最好**（高意图人群） | 中（靠量） |
| 风险 | 可能等一年没动静 | 做重了但没人用 | 内容合规要拿捏 |

**选择：C 为主线，A 作为底座，B 作为变现层。**

不是三选一，是三层。理由：

- **C 是原始需求本身。** 你的爆款不是因为"有人想看汉坦数据"，是因为
  **"我看到一条吓人的东西，想知道该不该慌"**。这个需求跟汉坦无关，跟传染病也只是弱相关——
  它跟"社交平台会持续生产恐慌"强相关。而社交平台会一直生产恐慌。
- **A 不是被动等待，是主动预置。** 下一次爆发才是真正的大流量。现在把管道做成
  "换个病种就能上"，那么下次热点出现时你能在**当天**上线，而不是当月。
  这才是把上次运气变成能力。
- **B 是唯一能收到钱的地方**（见第 6 节），但它需要 C 带来的持续在场感。

## 4. 落地：三层结构

### L1 · 传言体温计（核心，先做）
用户输入/点选一个正在传的说法 → 返回一张卡：

```
「XX 病毒在 YY 爆发了」
├─ 现在的可溯源状态：WHO / ECDC / 某国 CDC 最近一次提到它是 <日期>，说了什么
├─ 距中国大陆：<国家级距离>
├─ 中国大陆有没有：有 / 没有 / 暂无可溯源信息
└─ 判断：⚪ 没有可溯源依据 · 🟢 有通报但离得远 · 🟡 需要关注
```

关键设计约束（都是既有铁律的延伸）：
- **只做描述，不做预测**。不写"会不会传到中国"。
- **"暂无可溯源信息"是一个合法答案，而且要理直气壮地显示。**
  这正是它区别于传言的地方——传言从不承认自己没有依据。
- **不为每个病种建病例账本**。汉坦的 `outbreak-status.json` 那套逐国确诊/疑似核对
  是最贵的部分，只对"当前主线疫情"做。其余病种只做**事件级**（谁在什么时候通报了什么）。
- 病种范围：中文互联网真正会传的那几个——流感/甲流、诺如、登革热、基孔肯雅热、猴痘、
  麻疹、百日咳、狂犬病、埃博拉。**不是"所有传染病"**。

工程上最小改动：`QUERIES` 加行 → 抽取器加病种标签 → 首页从"单疫情"改成"按病种分卡"。

### L2 · 季节页（回访理由）
"现在这个季节，中文互联网在传什么 / 官方在通报什么"。
数据粒度按 spike 结论诚实收口：**国内到省，国外到国家**。
冬季流感是天然主场——中国流感监测周报每周更新、可引用、且搜索量巨大。

### L3 · 出国目的地健康页（变现层）
按 spike 结论，这是数据最顺的一块（WHO DON + 美 CDC Travelers' Health + ECDC 全是国家级）。
受众高意图（留学/外派/旅行），季节性明确（寒暑假前）。**这层是收钱的地方，不是走量的地方。**

## 5. 分发：把已验证的动作做成流水线

你唯一验证过的获客动作是"一张截图"。所以：

1. **海报是产品，不是附属品。** 本次修了两个硬伤：
   - 海报从来没有配中文字体（`@vercel/og` 只内嵌拉丁字集）——中文大概率一直渲染成豆腐块。
     这可能就是它一直没被用起来的原因。已改为按需拉取 Noto Sans SC 子集（每字重约 6 KB）。
   - 海报 C 位是「HPI 31 一般关注」——陌生人看不懂，且"一般关注"读起来像在报警。
     已改为首屏那句判断。
   - `/share` 只在站点页脚有一个链接，首页正文没有入口。已在正文加 CTA。
2. **固定动作**：每天一张卡，有事说事，没事就说"已经 N 天没有新增确诊"。
   **平静期的卡片本身就是内容**——"没事"是稀缺信息。
3. **主场是小红书和微信，不是网页。** 网页只负责"被搜到 + 生成图"。
4. 可选：公众号做承接。**关注 = 订阅**，平台替你扛 PII 合规——这正好补上本次
   下线的邮箱/手机订阅（见第 7 节）。

## 6. 变现：个人主体能做什么

> 以下门槛以平台当前规则为准，动手前请自己再核一遍。

| 路径 | 门槛 | 天花板 | 合规 | 建议 |
|---|---|---|---|---|
| **B 端定制简报**（留学中介 / 外派企业 / 旅行社要一份"目的地健康说明"给客户） | 需要 L3 做出来；开票需升个体工商户 | **最高**，单笔可观 | 干净——卖的是信息整理，不是医疗意见 | ⭐ 主攻 |
| **知识付费**（出国健康准备清单：哪些国家要黄热病证书、去哪个国际旅行卫生保健中心、提前多久打） | 小报童/知识星球支持个人收款 | 中 | 干净——是**流程清单**不是医疗建议 | ⭐ 早做，验证付费意愿 |
| **小红书品牌合作** | 蒲公英需实名 + 粉丝门槛（约 1000） | 中 | ⚠️ 接保健品 = 亲手拆掉信任护城河 | 只接得住的：旅行装备、消毒清洁 |
| **公众号流量主** | 500 粉 | 低（个人号量级很小） | 干净 | 顺手开，别指望 |
| **联盟带货**（驱蚊/防蜱、旅行药箱、净水片） | 淘宝客/京东联盟支持个人 | 低-中 | 只在"目的地建议"语境里带，否则违和 | 后置 |
| ❌ 保险佣金 | 需保险经纪资质 | — | **红线** | 不做 |
| ❌ 药品/医疗器械 | 需资质 | — | **红线** | 不做 |
| ❌ 付费问诊/健康咨询 | — | — | **红线**（小程序类目 = 工具/资讯，永不医疗） | 不做 |

**关于升级个体工商户**：成本低（几百块、约一周），解锁微信支付、服务号认证、开票、
以及"能签合同收 B 端的钱"。**在你有第一个 B 端意向之前不用急；有了就立刻办。**

**顺序建议**：先用 L3 免费页养出高意图人群 → 用知识付费验证"他们愿不愿意花钱" →
有人付钱了再升个体工商户 → 再去谈 B 端。不要反过来。

## 7. 明确不做

1. **不做多疾病实时仪表盘。** 每个病种一套病例账本 = N 倍数据债，而且大部分病种
   根本没有 WHO DON 那种结构化源。事件级足够。
2. **不做预测/预警/风险预报。** 合规红线，也不是你的能力边界。
3. **不自建订阅名单。**（本次已下线邮箱/手机订阅——它同时违反了你自己的隐私政策和 PRD 铁律，
   而且从未真正发出过任何通知。）用户资产放在公众号/小红书，平台替你扛合规。
4. **不做城市级发病率。** spike 已证明：公开可引用的最细粒度是省级。硬做就是虚假精度。
5. **不再往 web 端加功能。** 主受众在微信里。

## 8. 四个决定（2026-08-28 已定，并已落地）

1. **主线选 C** ✅。PRD 的 OUT-OF-SCOPE #4 已改成"V2 范围"，并写死四条约束：只做事件级、
   绝不为第二个病种建病例账本、病种是有限清单、"WHO 没有条目"必须是一等答案。
2. **病种清单** ✅ 流感 + 登革热 + 诺如（你批的三个）+ 汉坦。**另加了埃博拉与 Mpox**——
   小程序首页本来就有这两张写死的静态卡，把它们接到真实 DON 日期上，是把占位补实，不是加新面。
3. **L3 并行做静态版** ✅ `/destinations`，10 个目的地，**只做网页**（可被搜索/可被引用，
   正是网页端还值得投入的那一件事）。不给疫苗/入境/医疗建议，只汇总 WHO 通报 + 官方入口链接。
4. **汉坦收尾** 🟡 部分完成。首页已降为「深度追踪：汉坦 / 安第斯型」并链到事件页；
   事件页本身还是进行时口吻，改写成存档口吻是下一个切片。

### 实际落地的东西

  → `disease_watch.py` + `destination_watch.py` → 两个新 JSON。

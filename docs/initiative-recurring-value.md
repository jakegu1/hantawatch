# Initiative — 让工具长期有用（季节科普 + 现状雷达 + 留学/出国）

> 状态：**探索中（V2 方向）**，gated on 数据可行性 spike（T0）。
> 战略目的：汉坦平静后，给平静期一个**常年回访的理由**，把工具从"爆发期告警"升级为"长期有用"。
> ⚠️ 本方向**重新打开** v1 PRD 的 OUT-OF-SCOPE #4（多疾病）与 #5（城市个性化）——即把它们从"本版不做"挪进**V2 范围**。v1 的"可截图转发的安心判断"不取消，先后/并行关系见"开放问题"。

## 已锁定的设计决策（来自规划对话）
1. **不做预测/预报/预警**——只做**描述性**：历史档案 + 当下现状；结论由用户自己下，工具只摆事实（合规护盾）。
2. **地理粒度按数据真实可溯源层级"四舍五入"**——数据只到省/国家就只显示到省/国家，绝不假装到市/区（等同"距离取整 100km"铁律）。诚实粒度本身是信任护城河。
3. **现状雷达用"事件模型"而非"发病率"**——展示"近期被官方通报/监测到的疫情事件（带 source+asOf）"，不报本地发病速率（速率无源、且涉越权发布风险）。这是采集器**已在为汉坦做的事**。
4. **国内城市 与 留学/出国国家级 并行做**（不是先国内后全球）。
5. **季节科普日历要比"纯静态科普"更聪明**——静态科普为底座 + 有可溯源信号时**动态点亮**的一层；"更聪明"的具体形态在 spike 出数据后再共同细化（聪明程度被数据上限约束）。
6. **选城市/目的地用本地缓存（无 PII）**——合规，卡点是数据不是隐私。
7. 任何展示数字仍受铁律约束：`source`+`asOf`、guard 覆盖、暂无数据>假数据、不虚假精度。

## 功能清单（gated on spike）
- **F-A 季节科普日历**：静态科普底座 + 动态点亮层；国内 + 目的地并行。
- **F-B 历史档案**：某地过去一段时间的可溯源流行病历史（粒度由 spike 定）。
- **F-C 现状雷达**：当下"被官方通报在流行什么"，事件模型（粒度由 spike 定）。
- **F-D 留学/出国目的地健康概览**：国家级，吃 WHO DON / ECDC / 美 CDC travel 等可引用源；常年需求、不依赖爆发。

## Spike 结论（T0，2026-06-24，owner: Claude；已实证抽查）

### 逐源体检
| 源 | 地理粒度（最细） | 维度 | 频率 / 滞后 | 可引用 / 格式 | 判定 |
|---|---|---|---|---|---|
| 国家疾控局 全国月报（ndcpa.gov.cn） | **仅全国**，无省/市/区拆分（已抽查 2026-05 月报证实） | 按病种类别 + 各病种发病/死亡 | 月度，月结后约 10 天发布 | ✅ 可引用，散文 HTML、需解析 | 全国级可用 |
| 省级 CDC 月报（如广东 cdcp.gd.gov.cn） | **省级**，无地市/区拆分 | 省总 + 按类别/病种 | 月度 | ✅ 可引用，散文 HTML，**各省各自发布、无统一接口** | 省级可用（需逐省接） |
| WHO DON（who.int，有 JSON API + 公开页） | **国家/地区级**，事件型 | 疫情事件（病种/国家/时间/病例数在正文，**字段需解析**） | 事件触发，带 PublicationDate/LastModified（=asOf） | ✅ 可引用；API 公开性/鉴权需实现时确认；正文需 LLM/规则抽取 | 国家级最强 |
| 美 CDC Travelers' Health / ECDC | **国家级**，4 级风险分级 | 旅行健康通报（病种/目的地） | 事件触发 | ✅ 可引用，网页（可抓） | 留学/出国主力源 |

### 决定性发现
- **国内发病数据公开可引用的最细粒度 = 省级（月度、按病种）；全国级更全。地市/区县级：不存在公开可引用版本。**
- **国际 = 国家级事件型（WHO DON + 旅行通报），原生就是国家粒度——无虚假精度问题。**
- 因此**"留学/出国国家级"在数据上比"国内城市级"更可行**，且常年需求、不依赖爆发——更解平静期问题。

### 逐功能 go/no-go（真实粒度）
- **F-A 季节科普日历** → ✅ **GO**。静态科普底座任意粒度可用；"更聪明"的动态点亮层绑到**省级（国内）/ 国家级（出国）**信号，月度/事件频率。
- **F-B 历史档案** → 🟡 **GO，但粒度降到省/全国**（月度、按病种）。**"你的城市的历史曲线"做不到**——UI 须从"城市"改为"你所在省份 / 全国"。
- **F-C 现状雷达** → 🟡 **部分 GO，事件模型 + 省/国家级**。诚实形态="近期[你所在省/目的地国家]**被官方通报**的疫情事件 + 当前季节高发病（科普）"。**"区县级 / 正在流行的发病率" = 🔴 否决**（无源 + 虚假精度 + 越权风险）。
- **F-D 留学/出国国家级** → ✅ **GO，最可行**，建议**优先级最高**。

### 对设计的硬约束（落到后续切片）
1. **选城市仍可做**，但数据映射到其**省份**，UI 明示"数据为省级"。城市→省映射=静态查表（无数据问题）。
2. 现状雷达用**事件模型**，不报发病率；不下探到区县。
3. WHO DON 正文非结构化——**结构化抽取（病例数/国家/病种）需解析层**，是 F-C/F-D 的真实工作量所在，须在那一步的 /goal 里单列。
4. 各省 CDC 无统一接口——国内省级历史=**逐省采集**的持续数据债，扩省要按 ROI 决定，别一次铺全国。

### 下一步建议（待 Jake 对齐）
- 优先级改为：**F-D（出国国家级，数据最顺）→ F-A（季节日历，复用 D 的国家源 + 国内省级）→ F-C（现状雷达，吃 WHO DON 解析）→ F-B（省级历史，逐省债最重、放最后）**。
- 即：**主场先押"留学/出国"**，国内以省/全国粒度诚实跟进，城市级历史降级或后置。
